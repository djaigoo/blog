# Casbin 权限管理框架介绍

## 什么是 Casbin

Casbin 是一个开源的权限管理（访问控制）库，用于在软件系统中实现灵活的权限控制（authorization）。它的核心目标是让开发者能够灵活地定义和执行访问控制策略，支持多种经典的访问控制模型，并提供跨语言支持。

**项目地址**：https://github.com/casbin/casbin  
**官方网站**：https://casbin.org

## 支持的访问控制模型

Casbin 支持多种访问控制模型，这些模型定义了 `subject`（主体，如用户或角色）、`object`（对象、资源）和 `action`（操作，如读写删除）之间的授权规则：

### 1. ACL（Access Control List）
传统的基于主体-对象-操作三元组的访问控制模型。

### 2. RBAC（Role-Based Access Control）
基于角色的访问控制，支持：
- 角色层次结构（角色继承）
- 多域（tenant/domain）
- 资源角色等扩展

### 3. ABAC（Attribute-Based Access Control）
基于属性的访问控制，可以根据资源或主体的属性（如拥有者、时间、状态等）进行控制。

### 4. RESTful 模式支持
支持资源路径模式匹配（例如 `/foo/*`、`:id`）以及 HTTP 方法控制。

### 5. Deny-overrides 和优先级支持
当存在冲突规则时，deny 可以覆盖 allow，还可以给 policy 规则设置优先级，用类似防火墙规则的方式控制优先顺序。

## 核心组件与原理

Casbin 的权限规则由三个主要组件构成：

### 1. Model（模型文件）
通常为 `model.conf`，定义了：
- 请求格式（request_definition）
- 策略格式（policy_definition）
- 效果（effect，允许或拒绝）
- 匹配逻辑（matchers）

模型文件定义了权限模型的结构和执行方式。

### 2. Policy（策略规则）
具体的权限条目，例如：
- "Alice 可以读取 data1"
- "Bob 拥有 admin 角色"
- "用户可以在工作时间访问系统"

这些规则基于模型定义的结构。

### 3. Enforcer（执行器）
在运行时加载模型与策略，然后判断某个请求是否被授权。通过 `Enforce(sub, obj, act)` 等接口进行权限检查。

## 支持的存储方式（Adapters）

策略可以存储在多种后端中：

- **文件**：CSV、JSON 等格式
- **内存**：临时存储
- **关系型数据库**：MySQL、PostgreSQL、Oracle 等
- **NoSQL 数据库**：Redis、MongoDB 等

此外，Casbin 还支持 "watcher" 机制，用于多节点间策略同步。

## 功能亮点

### 跨语言支持
Casbin 提供了多种语言的实现：
- Go（官方实现）
- Java
- Python
- Node.js
- PHP
- .NET
- Rust

### 灵活可扩展的模型
模型文件可自定义组合，支持混合使用 RBAC + ABAC 等复杂场景。

### RBAC 的角色管理
支持：
- 用户-角色映射
- 角色继承
- 资源也可以作为角色（资源角色）

### 模式匹配与路径支持
与 Web 或 REST API 路由结合时，可以使用类似 `/foo/*` 的路径匹配，以及 HTTP 方法控制。

### 策略优先级与 deny-overrides
支持控制规则之间的逻辑冲突时的取消策略与优先级。

## 使用示例（Go 语言）

### 1. 准备 Model 文件

创建 `model.conf`：

```conf
[request_definition]
r = sub, obj, act

[policy_definition]
p = sub, obj, act

[matchers]
m = r.sub == p.sub && r.obj == p.obj && r.act == p.act

[policy_effect]
e = some(where (p.eft == allow))
```

### 2. 准备 Policy 文件

创建 `policy.csv`：

```csv
p, alice, data1, read
p, bob, data2, write
```

### 3. 代码实现

```go
package main

import (
    "fmt"
    "github.com/casbin/casbin/v2"
)

func main() {
    // 创建 Enforcer
    e, err := casbin.NewEnforcer("model.conf", "policy.csv")
    if err != nil {
        panic(err)
    }

    // 权限检查
    if e.Enforce("alice", "data1", "read") {
        fmt.Println("授权通过")
    } else {
        fmt.Println("授权失败")
    }

    // 添加策略
    e.AddPolicy("charlie", "data3", "read")
    
    // 删除策略
    e.RemovePolicy("bob", "data2", "write")
}
```

## 应用场景

Casbin 非常适合以下场景：

1. **SaaS 多租户系统**：跨域、跨项目的权限模型
2. **Web/API 服务**：需要灵活定义资源路径、HTTP 方法的访问控制
3. **复杂角色结构**：系统角色结构复杂，或者权限由属性决定（ABAC）或需要混合模型
4. **多节点部署**：需要策略同步/更新

## 边界说明

Casbin 仅负责 **授权（authorization）**，并不处理以下内容：

- **用户认证（authentication）**：Casbin 不验证用户名/密码，不负责登录功能
- **用户或角色实体管理**：尽管它会管理用户与角色的映射，但不会替你做用户账户、密码、资料等管理功能

## 总结

Casbin 是一个功能强大且灵活的权限管理框架，特别适合中大型项目中对权限控制有复杂需求的场景。如果你的需求仅仅是简单的用户-角色-权限三者结构（小项目），Casbin 可能稍显复杂，但其灵活性在中大型项目中价值显著。

通过模型文件和策略的分离，Casbin 实现了权限规则的灵活配置和动态管理，是构建现代权限管理系统的优秀选择。
